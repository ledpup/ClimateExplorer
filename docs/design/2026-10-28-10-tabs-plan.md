## Design

### API

```razor
<Tabs SelectedTab="@ActiveTab" SelectedTabChanged="@OnTabChanged" AriaLabel="Dataset source" Class="dataset-browser-tabs mb-3">
    <Tab Name="Local">Local</Tab>
    <Tab Name="Global">Global</Tab>
</Tabs>
```

- `Tabs`: `SelectedTab` (`string?`), `SelectedTabChanged` (`EventCallback<string>`), `AriaLabel`
  (`[EditorRequired]`, per AGENTS.md), `Class`, `ChildContent`.
- `Tab`: `Name` (`string`, required), `ChildContent` (label), `Disabled` (`bool`).
- The `<Items>` wrapper goes away. The outer `<div class="climate-tabs …">` moves into the component
  (`Tabs` renders it and appends `Class`).

### Markup and semantics

```razor
<div class="climate-tabs @Class">
    <div role="tablist" aria-label="@AriaLabel" class="climate-tablist">
        <CascadingValue Value="this" IsFixed="true">@ChildContent</CascadingValue>
    </div>
</div>
```

`Tab` registers with its parent (on initialise, unregistering on dispose) and renders:

```razor
<button type="button" role="tab" id="@TabId" class="climate-tab @(IsSelected ? "is-active" : null)"
        aria-selected="@(IsSelected ? "true" : "false")" tabindex="@(IsSelected ? 0 : -1)"
        disabled="@Disabled" @ref="element" @onclick="SelectAsync" @onkeydown="Parent.OnKeyDownAsync">@ChildContent</button>
```

- ARIA tabs pattern with **automatic activation**, the same as clicking today. Roving `tabindex`:
  only the selected tab is in the Tab order. ArrowLeft/ArrowRight move to the previous/next enabled
  tab (wrapping), Home/End to the first/last. Each moves focus (`ElementReference.FocusAsync()`)
  and selects.
- No `aria-controls`: the panels belong to the parent. APG lists `aria-controls` as recommended, not
  required. A parent that wants the association can render `role="tabpanel" aria-labelledby="@tabs.IdFor(name)"`.
  `Tabs.IdFor(name)` is exposed for that and used at least in `DataSetBrowser` and `ClimateRecords`.
- `@onkeydown:preventDefault` can't be conditional per key in Blazor, and making it unconditional
  would swallow Tab. Arrow keys aren't prevented, which only matters when the page scrolls
  horizontally (it doesn't).
- The keyboard index maths (next/prev/home/end skipping disabled, wrapping) goes in a static
  `TabNavigation.NextIndex(int current, int count, Func<int,bool> isDisabled, string key)` helper so
  it can be unit-tested.
- Many tabs on narrow screens: `overflow-x: auto` on the tablist, as Blazorise/Bootstrap does
  implicitly today. The active tab is scrolled into view on selection (`scrollIntoView({ block: "nearest", inline: "nearest" })`
  via a one-line interop, or `FocusAsync`, which scrolls when keyboard-driven).

replaces the seven header-only Blazorise tab strips, keeping the same
`SelectedTab`/`SelectedTabChanged` string API. The folder-tab styles move from `app.css` into the
component, and each strip gets an accessible name.

## Addendum — implementation (2026-10-28)

- **Tab ids:** `IdFor` is static, `Tabs.IdFor(tabsId, name)`, and `Tabs` takes an optional `Id` (the id prefix;
  generated when omitted). An instance method would need an `@ref`, which is null on the parent's first render.
  Characters that aren't valid in an id (spaces, brackets, `°`) become `-`, because the names include metric labels
  and dataset keys. `DataSetBrowser` and `ClimateRecords` make a per-instance id and wrap their content in
  `role="tabpanel" aria-labelledby=…`. In `ClimateRecords` that's everything below the strip, so the file's body is
  re-indented (`git diff -w` shows the real change).
- **Keyboard order:** tabs register in the order they're created, which isn't always document order (the "About
  curved trends" tab in `ChartTrendPanel` is an `@if` between existing tabs). On an arrow/Home/End key, `Tabs` asks
  `Tabs.razor.js` (`getTabIds`, imported on first use) for the tab ids in DOM order, then uses
  `TabNavigation.NextIndex`. Other keys skip the interop.
- **Re-rendering:** a `Tab` doesn't re-render when only its parent's `SelectedTab` changes, so `Tabs` calls
  `Refresh()` on each tab when the selection moves.
- **Tab stop when nothing is selected:** if `SelectedTab` matches no tab, the first enabled tab is the tab stop, so
  the strip can still be reached by keyboard. Clicking the already-selected tab doesn't raise `SelectedTabChanged`
  (`ClimateRecords` would otherwise reload).
- **Styles:** `Tabs.razor.css` styles `.climate-tab` with `::deep`, since `Tab` is a separate component. Bootstrap's
  `.nav-tabs` wrapped; the strip now scrolls (`overflow-x: auto`) instead. The focus outline is inset
  (`outline-offset: -4px`, white on the active tab) because the scroll container clips anything outside the tab.
  The 44px minimum height is under `@media (pointer: coarse)`, per AGENTS.md, so the desktop size is unchanged.
  `.trend-stats .trends-about-tabs` in `app.css` needed no rename: the class is still on the outer `.climate-tabs` div
  (now via `Class`).
- **Scoped margins:** `.recent-observation-tabs` (`RecentObservationTabs.razor.css`, now deleted) and
  `.location-dataset-metadata-tabs` were scoped rules on the wrapper div, which now belongs to `Tabs`, so they'd no
  longer match. Both were `margin-bottom: 1rem`; those strips pass `Class="mb-3"` instead. The unstyled
  `dataset-browser-tabs` class was dropped.
- **Tests:** the six planned `TabNavigationTests` plus `NextIndex_ArrowLeftPreviousDisabled_SkipsDisabled`,
  `NextIndex_AllOthersDisabled_ReturnsCurrent` and `IdFor_NameWithSpacesAndPunctuation_ReplacesThemWithHyphens`.
- AGENTS.md lists `Tabs / Tab` with the common components and no longer lists Tabs under Blazorise.
