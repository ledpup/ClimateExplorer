## Design

### Native `<dialog>` with `showModal()`

`showModal()` gives, natively: the top layer, an inert background (focus trap without code),
Escape → `cancel` → `close`, a `::backdrop`, initial focus (the first focusable element, or one with
`autofocus`), and focus returning to the opener on close. What we add: backdrop-click to close, the
open/close interop, scroll lock, and the header/body layout.

### API

```razor
<Modal @ref="modal" Title="Change location" Size="ModalSize.Large" Opened="OnModalOpened" Closed="OnModalClosed">
    ...body...
</Modal>

<Modal @bind-Visible="pipelineModalVisible" Title="Data Pipeline" Size="ModalSize.ExtraLarge">…</Modal>

<Modal @ref="modal" Size="ModalSize.Large">
    <TitleContent>@* markup title *@</TitleContent>
    <ChildContent>…</ChildContent>
</Modal>
```

| Member | Notes |
|---|---|
| `Title` (`string?`) / `TitleContent` (`RenderFragment?`) | One or the other. Rendered in an `<h2>` that the dialog's `aria-labelledby` points to. |
| `Size` (`ModalSize`: `Default` 500px, `Large` 800px, `ExtraLarge` 1140px) | Widths as Bootstrap's today. Full width minus a 0.5rem gutter on mobile. |
| `Visible` / `VisibleChanged` | Supports `@bind-Visible` (About). |
| `ShowAsync()` / `HideAsync()` | Imperative, for `@ref` callers. Keep `Show()`/`Hide()` names as aliases if that reduces churn in `Index.razor.cs` (calls `ChangeLocation.Show()`, which is `ChangeLocation`'s own method, so no change there). |
| `Opened`, `Closed` (`EventCallback`) | `Opened` after `showModal()` returns; `Closed` after the dialog's `close` event, whatever the cause (button, Escape, backdrop). |
| `RenderContentWhenClosed` (`bool`, default `false`) | Body isn't rendered while closed. This is the lazy behaviour `OverviewField` hand-codes today, and it makes every modal's content cheap until opened. |
| `ChildContent`, `Class`, captured attributes | |

### Markup and interop

```razor
<dialog @ref="dialog" class="climate-modal climate-modal--@SizeClass @Class"
        aria-labelledby="@titleId" @onclose="OnDialogClosed" @onclick="OnBackdropClick" @attributes="AdditionalAttributes">
    <div class="climate-modal-content" @onclick:stopPropagation="true">
        <header class="climate-modal-header">
            <h2 id="@titleId" class="climate-modal-title">@(TitleContent ?? (RenderFragment)(b => b.AddContent(0, Title)))</h2>
            <button type="button" class="climate-modal-close" aria-label="Close" @onclick="HideAsync">
                <i class="fas fa-xmark" aria-hidden="true"></i>
            </button>
        </header>
        <div class="climate-modal-body">@if (isOpen || RenderContentWhenClosed) { @ChildContent }</div>
    </div>
</dialog>
```

- **Backdrop click.** The content wrapper fills the dialog (the dialog has no padding), so a click
  that reaches the `<dialog>` itself landed on the backdrop. Hence `@onclick` on the dialog plus
  `stopPropagation` on the content. A future simplification is `closedby="any"` (native light
  dismiss), once it's Baseline.
- **`Modal.razor.js`** (collocated, imported like `ChartJsChart.razor.js`): `show(dialog)` →
  `dialog.showModal()`, and `close(dialog)` → `dialog.close()`. That's all.
- **Close sync.** Blazor supports `@onclose`/`@oncancel` on `<dialog>` (added in .NET 8). The
  `close` handler sets `isOpen = false`, raises `VisibleChanged(false)` and `Closed`. If this turns
  out unreliable across the render-mode handoff, fall back to a JS `close` listener calling a
  `DotNetObjectReference`.
- **Open sequence.** `ShowAsync()` sets `isOpen = true`, calls `StateHasChanged()`, awaits a render
  (a `TaskCompletionSource` completed in `OnAfterRenderAsync`) so lazy content exists before focus
  is placed, then calls `show`, then raises `Opened`.
- **Prerender.** The dialog renders closed. `Show` before interactivity is a no-op, because no
  consumer opens a modal on first render without user action. Index opens `ChangeLocation` in
  `OnAfterRenderAsync`, which is interactive by definition.
- **Scroll lock.** `html:has(dialog.climate-modal[open]) { overflow: hidden; }` replaces `.modal-open`.
- **Disposal.** If disposed while open, close the dialog in `DisposeAsync`, swallowing `JSDisconnectedException`.

### Styles (`Modal.razor.css`)

- Dialog: `padding: 0; border: none; border-radius: 16px` (AGENTS.md: modals 16px);
  `width: min(var(--modal-width), calc(100vw - 1rem))`; `max-height: calc(100dvh - 2rem)`;
  `box-shadow: var(--climate-shadow-panel)`. The content wrapper is a flex column, and the body scrolls (`overflow: auto`).
- `::backdrop { background: rgb(0 0 0 / 50%); }`
- Header: `background: #425f59; color: #fff;`, title `font-size: 1.25rem`, close button a 44×44

- Optional open transition (`@starting-style`, opacity/translate), disabled under `prefers-reduced-motion`.

## Manual checks (developer)

- Each modal opens centred at the right width (mobile: near full width), with the green header and
  the body scrolling for long content.
- Escape, the close button and a backdrop click all close it, and focus returns to the opener.
- Tab stays inside the modal. The page behind doesn't scroll.
- Change location: the search box is focused on open. Picking a location closes the modal.
- OverviewField popups don't instantiate content until opened. Reopening shows fresh content.
- Tooltips and dropdowns opened inside a modal render above it.

## Summary

A `Modal` component on `<dialog>`/`showModal()` replaces the five Blazorise modals, with a single
header style, lazy body content and `@bind-Visible` support. Focus trap, Escape, backdrop and focus
return are native, so the JS is two one-line functions. `OverviewField` and `ChangeLocation` lose
their hand-written lazy-content and focus-delay workarounds.

## Addendum — implementation notes

Shipped as planned, with these deviations:

- **Backdrop click is handled in `Modal.razor.js`, not with `@onclick` + `stopPropagation`.** A press that
  starts in the content and is released over the backdrop (selecting text, say) fires `click` on the
  `<dialog>`, which the Razor version would have treated as a backdrop click. The JS closes the dialog only
  when both `pointerdown` and `click` hit the dialog itself. So the module is `init(dialog)` returning
  `show`/`close`/`dispose`, rather than two one-line functions. It's imported lazily on the first
  `ShowAsync()`, so a modal that's never opened costs no interop.
- **Close sync uses `@onclose`.** Blazor (.NET 8+) registers `onclose`/`oncancel`, so no
  `DotNetObjectReference` was needed. `HideAsync()` only calls `dialog.close()`; `isOpen`,
  `VisibleChanged(false)` and `Closed` all happen in the `close` handler, whatever closed it.
- **The body only scrolls on mobile.** The `<dialog>` covers the viewport and is transparent, and
  `.climate-modal-content` is the visible box. On tablet and desktop the dialog itself scrolls the whole
  modal, as Bootstrap's did, so there's no inner scrollbar and nothing in the body (such as the
  Autocomplete menu) is clipped. On mobile (≤767px) the box fits the screen and only the body scrolls,
  which keeps the close button in view. A click on the dialog itself is still a backdrop click.
- **The box sits near the top, not vertically centred.** Its margin is the gutter (0.5rem on mobile,
  1.75rem from 768px), like Bootstrap's modal. Content that renders lazily or loads after opening (trend
  recalculation, nearby locations) would otherwise make a centred box jump.
- **No `Show()`/`Hide()` aliases.** Every caller moved to `ShowAsync()`/`HideAsync()`. `ChangeLocation`
  and `AboutData` keep their own public `Show()`.
- **`Visible` acts on changes only.** `OnParametersSet` queues a show/hide only when `Visible` changes,
  and `OnAfterRenderAsync` runs it. A parent that passes `Visible` without binding it can't reopen a modal
  the user closed. `ShowAsync()` from a `@ref` raises `VisibleChanged(true)` so a binding stays in step.
- **Close button** is 2rem square with a mouse and 44px for `pointer: coarse` (as the dropdown items),
  rather than 44px always. White icon, `#cfc` on hover, white focus ring.
- **Scroll lock pads for the lost scrollbar**, as Bootstrap did. `show()` measures the page's scrollbar
  into `--climate-modal-scrollbar-width` before `showModal()`, and the `html:has(dialog.climate-modal[open])`
  rule adds it as `padding-right`, so the page doesn't shift sideways. `scrollbar-gutter: stable` was
  tried first, but it shrinks the viewport for fixed elements, and the full-viewport dialog would leave an
  empty strip down the right edge.
- **Open animation** is a 0.15s fade/slide-down keyframe on `[open]`, only under
  `prefers-reduced-motion: no-preference`. No close animation.
- `AboutData`'s branching title became a `ModalTitle` string property, so it uses `Title`, not
  `TitleContent`. `TitleContent` has no consumer yet.
- `ChangeLocation` lost its `display: contents` wrapper `<div>`. Its `::deep` rules match from the body
  markup it renders itself. It still imports `Blazorise.Components` for `Autocomplete`. The 50 ms focus
  delay and `shouldFocusLocationSearch` stay until [13 Autocomplete](2026-10-28-13-autocomplete-plan.md).
- `AGENTS.md` lists `Modal` with the common components. `CONTEXT.md`'s "Modal Headers" section now
  describes `Modal`.
