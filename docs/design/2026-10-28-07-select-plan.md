## Design

### API: same names and parameters, so call sites barely change

```razor
<Select TValue="SeriesSmoothingOptions" Id="@($"smoothing-{ChartSeries.Id}")" Compact
        Value="@ChartSeries.Smoothing" ValueChanged="@OnSmoothingChanged">
    <SelectItem Value="SeriesSmoothingOptions.None">None</SelectItem>
    ...
</Select>
```

| Parameter | Notes |
|---|---|
| `Value` / `ValueChanged` | `@bind-Value` works too |
| `Compact` | Replaces `Size="Size.Small"` |
| `Disabled`, `Id`, `Class`, captured attributes (`aria-label`) | |
| `ChildContent` | `SelectItem`s |

`Select` is marked `[CascadingTypeParameter(nameof(TValue))]`, so `SelectItem`'s `TValue` is
inferred and call sites write `<SelectItem Value="…">` as today.

### Value mapping without string parsing

Blazorise round-trips values through string conversion. Ours avoids parsing:

- Each `SelectItem` registers with the cascaded parent on initialise and unregisters on dispose. The
  parent holds a `SelectValueMap<TValue>`: key string → `TValue`.
- The key is `BindConverter.FormatValue(value, CultureInfo.InvariantCulture)`. That handles enums
  (name), numbers, `Guid` and `string`. `SelectItem` renders `<option value="@key">`.
- On `@onchange`, the parent looks the key up in the map and raises `ValueChanged` with the
  **original** `TValue` instance. If the key isn't found (it shouldn't happen), it ignores the event.
- `<select value="@CurrentKey">`. Blazor applies a `select`'s `value` after its options render, so
  the initial selection is correct.

`SelectValueMap<TValue>` is a small pure class (`Register`, `Unregister`, `TryGetValue`, `KeyFor`),
so it's unit-testable without bUnit.

### Markup and style

```razor
<select id="@Id" class="climate-select @(Compact ? "climate-select--compact" : null) @Class"
        value="@CurrentKey" disabled="@Disabled" @onchange="OnChangeAsync" @attributes="AdditionalAttributes">
    <CascadingValue Value="this" IsFixed="true">@ChildContent</CascadingValue>
</select>
```

`Select.razor.css`, using the tokens:

- `appearance: none`; a background `#f8f8f8` (control); border `1px solid #c4d4d1`; radius 8px;
  colour `#425f59`; a chevron as an inline SVG `background-image` on the right; `padding-right: 2rem`.
- Default `min-height: 44px` (touch target). `--compact`: `min-height: 2rem; font-size: 0.875rem`.
  The compact chart-form selects are inside rows that already meet 44px per row; the manual check
  below covers it.
- Hover border/background `#cfc`; `:focus-visible` outline in primary green; disabled at 60% opacity.

### Accessible names (fixed in the same change)

- In the chart forms (`ChartSeriesView`, `ChartSeriesTrendControls`, `AggregationOptions`), turn
  `<span class="form-label">` into `<label class="form-label" for="@id">` and give the `Select` a
  matching `Id`. Ids must be unique per series card, so suffix them with the series id. There are 18
  `form-label` spans, some of which label checkboxes/text inputs and are handled by plans 08 and 09.
  The CSS class stays, so styling is untouched.
- Where there's no visible label (`ClimateRecords`, `Locations`, `RecentObservationsPanel`), add an
  `aria-label`.
- Add to AGENTS.md: "`Select` needs a `<label for>` or `aria-label`."

### Coexistence

`Select`/`SelectItem` collide with Blazorise's. All 7 files move in one change and drop
`@using Blazorise`, fully qualifying any other Blazorise tags still present (`Blazorise.Check`,
`Blazorise.TextInput`, `Blazorise.Validation`, `Blazorise.Tabs` and so on, depending on which plans
have landed). Doing [08](2026-10-28-08-checkbox-plan.md) and [09](2026-10-28-09-text-input-validation-plan.md)
immediately before and after this plan (overall steps 7 and 10) keeps the qualifiers short-lived. `Size="Size.Small"` → `Compact`.

Then delete the `.form-select` rules from the 6 scoped CSS files and `app.css`, keeping any
layout-only rules (widths, gaps) against `.climate-select` via `::deep`.

## Summary

A small native `Select<TValue>`/`SelectItem<TValue>` with the same `Value`/`ValueChanged` API
replaces the 21 Blazorise selects. Values map back via a key→value dictionary instead of string
parsing, and the styling moves onto the climate tokens. The 17 unnamed selects get proper `<label for>`
or `aria-label` names in the same change.

## Addendum — implementation (2026-10-28)

- Done in the same change as [09 TextInput](2026-10-28-09-text-input-validation-plan.md), because `ChartSeriesView`
  and `ChartSeriesTrendControls` use both. No `Blazorise.*` qualifiers were needed except `Blazorise.Tabs`/`Blazorise.Tab`
  in `ClimateRecords`.
- Every select is `Compact`, including `AggregationOptions` "Grouping days", which had no `Size` in Blazorise. At the
  44px default it stood out next to the other chart-form controls.
- There are 22 selects, not 21: `ChartSeriesTrendControls` has a third (`TrendWindow`) next to the disabled placeholder.
- `SelectValueMap` counts registrations per key. When Blazor swaps one `SelectItem` for another with the same value
  (for example the "Statistic" select switching to its single disabled "None" item), the new item registers before the
  old one is disposed; without the count, the dispose would remove the key the new item still needs. There's a test for
  it. `SelectItem` also re-registers when its `Value` changes, because `@foreach` can reuse an item for a different value.
- Styling: shared `.climate-control` in `app.css` (from plan 09) plus `Select.razor.css`. New tokens
  `--climate-color-control-border` (`#c4d4d1`) and `--climate-color-danger` (`#a00000`). The chevron is in the primary
  green. Unlike Bootstrap's `.form-select`, the select isn't `width: 100%` by default. The chart forms and
  `AggregationOptions` set that with `::deep .climate-select`. The `width: auto` overrides in `ClimateRecords` and
  `Locations` are gone because they aren't needed now.
- Labels: every chart-form select gets a per-instance id (`series-{guid}-…`, `trend-{guid}-…`, `aggregation-{guid}-…`,
  `add-trend-series-{guid}`) and a `<label class="form-label" for>`. `ChartSeriesTrendControls` drops its `aria-label`s
  because the visible labels say the same thing. `AddTrendSection` keeps "Series to add a trend to", which is more
  specific than its visible "Series". `RecentObservationsPanel` already had a `<label for>`, so `ElementId` just became
  `Id`. `ClimateRecords` (Data type, Month, Day, Records per page) and `Locations` (Country, Heating score, Locations per
  page) get `aria-label`s.
- Small additions next to the selects: the `AggregationOptions` "Threshold (%)" number input got a `<label for>`, and
  the `Locations` search box got `aria-label="Search locations"`.
- `RecentObservationsPanel.razor.css` had `.recent-observations-config-control select { width: 10.25rem }`. Without
  `::deep` it never reached the Blazorise select, so the select filled the row. It's now `::deep .climate-select`, so
  the comparison-range select matches the 10.25rem date box next to it. That's a visible change; check it by eye.
- AGENTS.md lists `Select`/`SelectItem` (and `TextInput`) as common components, including the `<label for>` /
  `aria-label` rule, and no longer lists `Select` under Blazorise.
