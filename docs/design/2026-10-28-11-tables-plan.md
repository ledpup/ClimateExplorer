## Current state

Five Blazorise tables in four files:

| File | Options | Notes |
|---|---|---|
| `ClimateRecords.razor` (×2: results and placeholder) | `Striped` | `colour-col`, `top-percent-col`, `TextAlignment` Center/End, `<Strong>` in headers |
| `ChangeLocation.razor` | `Striped` | 10 placeholder rows while loading; a `Blazorise.Link` per row (handled in [15](2026-10-28-15-simple-markup-replacements-plan.md)) |
| `HeatingScoreInfo.razor` | `Narrow Striped` | Current row highlighted with `Color="Color.Info"` |
| `Pages/Locations.razor` | `Striped`, `Class="locations-table"` | **Sortable headers: `TableHeaderCell` with `@onclick` and inline `cursor: pointer`.** Not keyboard accessible, no `aria-sort`. |

Blazorise renders Bootstrap markup (`table table-striped table-sm`). Our `table.css` (98 lines)
already restyles `table.table` heavily (header colours, borders, hover, colour column), and
`app.css` has global `td:nth-child(n+2)` / `th` rules. UI test `ChartTests.cs` selects
`.modal-body .table-card a`.

## Decision: plain HTML, no component

A `Table`/`TableRow`/`TableCell` component family would only rename HTML elements. It adds render
cost and no behaviour. The value Blazorise added was the Bootstrap class names, which we're removing.
So: write `<table class="climate-table">` / `<thead>` / `<tr>` / `<th>` / `<td>` directly, and put
all styling in `table.css`. (If a wrapper ever becomes useful, for example a responsive scroll
container with a caption, that's a `TableCard` component around the `<table>`, not a cell-level family.)

The existing `.table-card` / `.table-header` / `.table-footer` wrappers stay as they are.

## Changes

### `table.css`

1. Rename selectors `table.table` → `table.climate-table`. A new class name means Bootstrap's
   `.table` rules stop applying immediately, rather than when Bootstrap is removed.
2. Port the Bootstrap base rules we rely on, now that `.table` no longer supplies them:
   `width: 100%; border-collapse: collapse; caption-side: bottom;`, cell `padding` (already set),
   `border-bottom: 1px solid #dee2e6`-equivalent using our `#c4d4d1`/`#eef1f0` greys, and `vertical-align`.
3. Modifiers:
   - `.climate-table--striped tbody tr:nth-child(odd) td { background: #f7faf9; }`
     (replaces `table-striped`; pick the colour to match today's stripe).
   - `.climate-table--compact` (replaces `Narrow`/`table-sm`): `padding: 0.25rem 0.5rem`.
   - `tr.is-highlighted td { background: var(--climate-color-tab-surface); }` (replaces `Color.Info`
     on the HeatingScore row).
   - Alignment helpers on cells: `.cell-center { text-align: center; }`, `.cell-end { text-align: end; }`.
4. Move the global `td:nth-child(n+2)` / `th` rules from `app.css` under `.climate-table` so they stop
   affecting the chart tooltip table and the trend-stat tables.

### Markup (mechanical)

| Blazorise | HTML |
|---|---|
| `<Table Striped>` | `<table class="climate-table climate-table--striped">` |
| `<Table Narrow Striped>` | `<table class="climate-table climate-table--striped climate-table--compact">` |
| `TableHeader` / `TableBody` / `TableRow` | `thead` / `tbody` / `tr` |
| `TableHeaderCell` | `<th scope="col">` |
| `TableRowCell` | `td` |
| `TextAlignment="TextAlignment.Center"` / `.End` / `.Start` | `class="cell-center"` / `cell-end` / (nothing) |
| `<Strong>` | `<strong>` |
| `Color="@(… ? Color.Info : …)"` on a row | `class="@(… ? "is-highlighted" : null)"` |

`Table*` and `Strong` collide with nothing in Common, so this doesn't need qualifiers. Files keep
`@using Blazorise` if they still use other Blazorise components.

### Sortable headers in `Locations.razor` (accessibility fix)

Replace `<TableHeaderCell @onclick=… Style="cursor: pointer; …">Name <i class="fas fa-sort…"></i></TableHeaderCell>` with:

```razor
<th scope="col" class="name-col" aria-sort="@AriaSort("name")">
    <button type="button" class="sort-button" @onclick='() => OnSortChanged("name")'>Name <i class="@SortIconClass("name")" aria-hidden="true"></i></button>
</th>
```

`AriaSort(column)` returns `"ascending"`/`"descending"` for the active column and null otherwise. It
goes in `Locations.razor.cs` next to the existing sort-icon logic. `.sort-button` resets button
styles (inherits font/colour, full cell width, left/centre aligned to match the column), and the
inline `cursor`/`user-select` styles move into `Locations.razor.css`.

### UI test

`ChartTests.cs` `.modal-body .table-card a` → `.climate-modal-body .table-card button.climate-link-button`.
This depends on plans 06 and 15; update the selector in whichever change lands last.

## Manual checks (developer)

- The four pages/panels look the same: header colours, striping, hover, colour column, alignment,
  compact heating-score table with its highlighted row.
- Locations: headers sort by click **and** keyboard (Tab + Enter/Space). The screen reader
  announces the sort state.
- Trend-stat tables and the chart tooltip table are unaffected by the moved `td`/`th` rules.

## Summary

The five Blazorise tables become plain HTML tables with a `climate-table` class and a few modifiers
(striped, compact, highlighted row, cell alignment). The styling `table.css` already did is kept,
and the Bootstrap base rules it relied on are added. The Locations sort headers become real buttons
with `aria-sort`.
